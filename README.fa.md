# md2pdf

یک فایل Markdown فارسی را به PDF راست‌به‌چپ تبدیل می‌کند: قلم IRANSans، متن
هم‌تراز (justify)، جدول‌های استایل‌دار، و دیاگرام‌های mermaid به‌صورت برداری.

<div dir="ltr">

```bash
md2pdf report.md                                  # -> report.pdf
md2pdf report.md -o out.pdf -s "نسخه ۱٫۰ — گزارش تحویل"
```

</div>

خروجی به‌صورت پیش‌فرض همان مسیر ورودی با پسوند `.pdf` است.

## سیستم‌عامل‌های پشتیبانی‌شده

| سیستم‌عامل | وضعیت |
|---|---|
| macOS | پشتیبانی‌شده و تست‌شده (Apple Silicon و Intel) |
| Linux | پشتیبانی‌شده — همان مسیر کد؛ Chrome/Chromium در مسیرهای متداول پیدا می‌شود |
| Windows | از **WSL** استفاده کنید و دستورهای Linux را دنبال کنید |

نقطه‌ی ورود یک اسکریپت `sh` است، پس روی ویندوز به WSL یا Git Bash نیاز دارد.
زیر Git Bash می‌توانید مستقیم `python md2pdf.py …` را هم صدا بزنید؛ Chrome و
Edge در مسیر `C:/Program Files/…` هم جست‌وجو می‌شوند.

## نصب

<div dir="ltr">

```bash
./install.sh                 # بررسی پیش‌نیازها، سپس لینک در ~/.local/bin
./install.sh /usr/local/bin  # یا هر مسیری که روی PATH هست
./install.sh --check         # فقط گزارش پیش‌نیازها، بدون هیچ تغییری
```

</div>

نصب با symlink انجام می‌شود نه کپی، پس هر به‌روزرسانی در این پوشه بلافاصله روی
دستور نصب‌شده اعمال می‌شود. اجرای مستقیم `./md2pdf` از داخل همین پوشه هم بدون
نصب کار می‌کند.

**`install.sh` هیچ‌چیزی را برای شما نصب نمی‌کند.** پایتون، Node و Chrome
بسته‌های سطح سیستم‌اند و مسیر به‌روزرسانی خودشان را دارند؛ یک ابزار تولید سند
جای مناسبی برای نصب بی‌صدای یک مرورگر روی ماشین شما نیست. کاری که می‌کند این
است که بررسی کند چه چیزی هست و برای هرچه نیست، دستور مخصوص سیستم‌عامل شما را
چاپ کند:

```

اگر پیش‌نیاز الزامی غایب باشد با کد خروجی غیرصفر تمام می‌شود، اما symlink را
می‌سازد — تا بعد از نصب آن وابستگی، کار دیگری نمانده باشد. IRANSans هشدار است
نه خطا: قلم جایگزین اعمال می‌شود و PDF ساخته می‌شود، فقط آن شکلی که باید
نمی‌شود — و همین نوع خرابی است که ارزش دارد به شما گفته شود.

## گزینه‌ها

| گزینه | کاربرد |
|---|---|
| `-o, --output` | مسیر خروجی (پیش‌فرض: نام ورودی با پسوند `.pdf`) |
| `-s, --subtitle` | زیرعنوان، زیر نخستین تیتر |
| `--no-cover` | نخستین `#` را یک تیتر معمولی بدان، نه عنوان روی جلد |
| `--margins` | حاشیه‌ی `@page` در CSS (پیش‌فرض `18mm 16mm 20mm 16mm`) |
| `--keep-html` | نگه‌داشتن HTML میانی کنار خروجی، برای عیب‌یابی |
| `--timeout` | میلی‌ثانیه انتظار برای رسم دیاگرام‌ها (پیش‌فرض ۶۰۰۰۰) |

## پیش‌نیازها

| نیاز | توضیح |
|---|---|
| Python 3.8+ | wrapper خودش یک مفسر سالم پیدا می‌کند؛ با `PYTHON=…` قابل تعیین است |
| Node 22+ | از `PATH`، از `~/.nvm`، یا با `NODE=…` |
| Chrome / Chromium / Edge | با `CHROME_PATH=…` قابل تعیین است |
| قلم IRANSans | اختیاری؛ در نبودش: Vazirmatn ← B Nazanin ← Geeza Pro ← Tahoma |

هیچ `npm install` لازم نیست: مرحله‌ی PDF، مرورگر Chrome را از طریق DevTools
Protocol و با WebSocket داخلی خود Node راه می‌اندازد، و `assets/mermaid.min.js`
هم درون مخزن است — پس ابزار آفلاین کار می‌کند.

## Markdown پشتیبانی‌شده

تیترها (`#` تا `####`)، پاراگراف، **پررنگ**، *مورب*، `کد`، ~~خط‌خورده~~،
پیوند، تصویر، فهرست‌های `-` و `1.`، نقل‌قول `>`، جدول `|`، خط جداکننده `---`،
بلوک کد، و دیاگرام‌های ```` ```mermaid ````.

نخستین `#` به عنوان روی جلد تبدیل می‌شود و هرچه میان آن و نخستین `---` باشد
یک بلوک متادیتا در نظر گرفته می‌شود — این بلوک هم‌تراز نمی‌شود، چون justify
کردن دو خط که یک نام فایل بلند در خود دارند، آن‌ها را در عرض صفحه می‌کشد.
برای سندهای بدون صفحه‌ی عنوان از `--no-cover` استفاده کنید.

## چرا مرورگر و نه فایل ورد

جهت فقط یک بار اعلام می‌شود، روی `<html dir="rtl">`، و همه‌ی قواعد چیدمان با
ویژگی‌های منطقی (`margin-inline`، `text-align:start`) نوشته شده‌اند؛ پس چیزی
برای آینه‌کردن دستی نمی‌ماند و پیاده‌سازی bidi مرورگر کار را انجام می‌دهد.

یک فایل `.docx` چهار سوییچ جداگانه‌ی راست‌به‌چپ را حمل می‌کند — `w:bidi` روی
section، `w:bidi` روی هر پاراگراف، `w:rtl` روی هر run، و `w:bidiVisual` روی هر
جدول. از آنجا که ظرف‌های ویژگی در WordprocessingML از نوع `xsd:sequence` هستند،
Word هر کدام از این‌ها را که در جای اشتباهی از XML نشسته باشد **بی‌صدا نادیده
می‌گیرد**. سندی که در یک نمایشگر درست به نظر می‌رسد و در Word نیمه‌چپ‌به‌راست
است، دقیقاً از همین‌جا می‌آید.

## دو نکته که خوب است بدانید

**توکن‌های لاتین از نظر bidi ایزوله می‌شوند.** در یک پاراگراف راست‌به‌چپ،
رقم‌های `2026-09-13` چپ‌به‌راست‌اند اما خط تیره‌ها از نظر bidi خنثی‌اند؛ بدون
ایزوله‌سازی، گروه‌ها جابه‌جا می‌شوند و تاریخ به شکل `13-09-2026` در می‌آید —
یعنی یک روز دیگر. توکن‌هایی که با `-_./:@+` به هم چسبیده‌اند در یک span ایزوله
پیچیده می‌شوند. ارقام فارسی عمداً دست‌نخورده می‌مانند: کلاس bidi آن‌ها AN است
و از پیش درست نمایش داده می‌شوند.

**دیاگرام‌ها در همان مرحله‌ی مرورگر رسم می‌شوند.** بلوک‌های mermaid پیش از چاپ
در صفحه کشیده می‌شوند، پس در PDF به‌صورت SVG برداری می‌نشینند نه تصویر، و هیچ
مرحله‌ی جداگانه‌ای با `mermaid-cli` لازم نیست. mermaid چیدمانش چپ‌به‌راست است
و فقط برچسب‌هایش فارسی‌اند؛ شکل‌دهی آن‌ها را خود مرورگر درست انجام می‌دهد.
